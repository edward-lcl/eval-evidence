## Disposition consistency

The register does not reject any verified integrity need. It rejects scope expansion
implicitly by deferring work to named adoption evidence rather than building a runner,
dashboard, registry, signing system, or generalized plugin system in this episode.
The PR review's two implementation blockers are fixed in the follow-up code and tests.
The other dispositions remain bounded by their named adoption triggers rather than
expanding this work into a runner, dashboard, registry, signing system, or generalized
plugin system.

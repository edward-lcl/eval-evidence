## 1. Verdict (one paragraph)

The receipts support a combination, not a single outcome: **(2) campaign provenance with no new concept + (8) most state is native and Eval Evidence should shrink** are the best-supported pair; **(4) publication tooling is the biggest single hole** is *mostly* true but not *only* (three Harbor-side gaps and one archive/ingest gap are not publication tooling); **(6)** and **(7)** are true only as per-field / per-layer qualifiers — the *arithmetic* of every real claim walked (four leaderboard rows and one paper cell, five ecosystems) was reproduced to full precision retrospectively, but in every case the *rule* was recovered by numerical matching against candidate policies rather than read from any record, and *instrument identity* (harness commit, image digest, dataset revision, adjudication of duplicates/dispositions) was UNAVAILABLE or moving; **(1)** holds only in the degraded sense "a missing *record*, not a missing *abstraction*" (the TB2.1 `submissions/*.json` + `metrics.py` pair already is that record and lives, correctly, in the leaderboard layer); **(3)** holds for vocabulary (PROV-DM, Inspect's `invalidation`, EEE, in-toto) and fails for solution (no adopter, no per-field "unavailable", Provenance Run Crate drops skipped steps); **(5)** is not supported — five different evaluators exhibit the same four failure classes (denominator, rule, instrument pin, row state) — though a positive portability claim remains UNAVAILABLE until a translation is run. The strongest formulation assemblable from the lanes (claim-class-specific required-edge sets + a PROV-shaped per-transition record emitted "as a diff against the trivial case", with per-field evidence state) survives most counterexamples but is broken by six: private variant testing / selective disclosure, provider identity behind a stable name, retrospective retry/rerun history, contamination/verifier-validity/interpretation (out of scope by design), **completeness of the transition set** (a per-transition record cannot certify that a transition — a merged submission, a rescoring — was not silently omitted; only an *expected set* held by a different actor can), and materiality/human dispositions (representable, never mechanical). One caveat on the convergence itself: all eight lanes read the same eval-evidence docs, which already contain the counter-hypothesis (DECISION_GATE §6, STATE_REGISTER "Counter-hypothesis" rows), so the *language* of "shrink" is partly primed; the *empirical* walkbacks (L2, L3, L4, L5, L7) are not primed and independently locate the failures at the row/aggregate layer. My recommendation: Eval Evidence keeps the evidence-state vocabulary with per-field source pointers and the content-reference primitive, drops per-trial sealing and the uniform coverage gate as headline features, reads `lock.json` and stops requiring ATIF for discovery, and spends its remaining budget on one public retrospective experiment (a per-row manifest retro-fit over all 142 TB2.0 rows) and one prospective Harbor experiment (retry tombstones + member digests + metric policy field) before writing anything.

## 4. Breaking the strongest formulation

### 4.1 The formulation (assembled from L8 §A/B, L6 §6(d), L2 §5.5, L7 §6.1, L5 §5)

**S1 — claim-class-specific required-edge sets.** Three classes (L8): R (record: single run; campaign aggregate), D (derived: A vs B; row supported by these evaluations; X caused Y), I (interpretive: out of infrastructure scope except citation edges). For each, a preregistered list of *which transitions must have a record*, with `unavailable` allowed and named (no uniform coverage score).

**S2 — per-transition record**, PROV-shaped: input identities (digests, not names) → selection rule / plan → transform name + version + code revision + parameters → output identity → reason for inclusion/exclusion → actor → timestamp → supersession/regrade link → uncertainty method. Emitted by Harbor at job close (attempts, aggregate, tombstones, metric policy) and extended by the publisher (cell ← aggregate, adjustments, validator version). Emitted only as a "diff against the trivial case" (L8 C-vi): when there are no retries/regrades/exclusions/version drift/adjustments, the record is a one-line attestation.

**S3 — per-field evidence state** with source pointer (`observed | derived | operator_asserted | provider_asserted | unavailable`, plus unresolved `conflicting`), so a mixed-provenance value (L4 C4) is visibly mixed.

### 4.3 What survives, ranked by how much it should change the design

1. **Completeness of the transition set.** A per-transition record certifies each recorded transition; it cannot certify that none was omitted (silent absence of a merged row, undisplayed folders, dropped trials under an unwritten predicate, a scan that stopped at [in-house value redacted]). The only fix is an *expected set* held at every layer by an actor/time different from the record — Harbor has it for trials (`lock.trials`, `n_total_trials`); no leaderboard studied has an "expected rows = merged submissions" invariant; L3's generator swallows the exception and `continue`s. **This is a real gap in S and it is not a schema; it is a checker that fails the build on `merged ≠ displayed`.**
2. **Externalities**: private variants, provider identity, funder access, contamination, verifier validity, interpretation frames. S can record `provider_asserted` facts and make absence visible; it cannot verify. Policy and audit did the work in every documented case (L7 §5 "What actually caught things").
3. **Retrospective retry/rerun/disposition history**: gone by construction (`rmtree`), or never written (PR #75). Prospective only.
4. **Materiality and human dispositions**: representable, never mechanical (L8 C-iii/C-iv). Reviewer judgment is irreducible here and S should say so rather than pretend.
5. **Closure of the input identity**: S must hash the closure of inputs (trials + PR corpus + judge traces + scan tables), and nothing inside S proves the closure is complete (L5 F3). Same root as (1).

Everything else in the counterexample lists is either caught by S or represented by S with a human decision attached. So the formulation is *sound* for the failure classes that dominated the record (denominator, rule, instrument pin, mixed provenance) and *honestly bounded* for the rest — provided it is deployed as a **gate with an expected set**, not as a passive record.

## 6. Ranked recommendation — what Eval Evidence should own

Ranked by (value the receipts support) ÷ (cost and overlap with native/prior art). Items 1–3 are "own"; 4 is "maybe, gated"; 5–9 are "stop owning / do not build".

1. **Per-field evidence state with source pointer** (`observed | derived | operator_asserted | provider_asserted | unavailable`, plus unresolved `conflicting`) — the structured-provenance companion record already sketched in RESEARCH_MAP. Receipts: L6 (no standard has it), L4 C3/C4 (mixed-provenance row), L7 class 4, L8 F7 (typed requested-vs-reported beats symmetric conflict). Change: express conflicts as *typed roles* (requested/reported/provider) rather than a symmetric "unavailable + conflict list".
2. **Content-reference primitive** (`safe_run_path`, `file_record`, `verify_referenced_files`) — small, portable, and exactly what a per-*row* offline bundle needs when the hub goes dark (`#177`) or when an archive is not content-addressed (L5's Actions-artifact archive). Own it as a library function, not as a "bundle product".
3. **A read-only reconstruction checker prototype** for Harbor job dirs (+ optional leaderboard submission JSON): recompute `mean`/accuracy under *declared* policies, emit the per-transition record as a diff-against-trivial, list `unavailable` edges, and — critically — check `expected == discovered == included` where an expected set exists (`lock.trials`, `n_total_trials`, submission `trials[]`). This is E1 in executable form; its output is a *proposal to Harbor/TB*, not a format.
4. **Comparison qualification** (lock diff + declared materiality policy + unresolved differences), consuming Harbor's own equality keys (`JobConfig.__eq__`, `TrialConfig.__eq__`, `TaskLock.__eq__`) — only after (3) and only if the Inspect translation (E6) shows the shape is not Harbor-specific.
5. **Stop**: the ATIF-gated discovery (0/17 real trials); ignoring `lock.json` (harness version present 17/17); the uniform `available_fraction` gate (claim-relative per L8 C-v; ceiling 0.70 per F14). These are fixes, not research.
6. **Do not own** the campaign record format — Harbor should emit expected attempts (has), retry tombstones (missing), member-trial digests at job close (missing), metric transform version + null policy (missing), regrade lineage (has). Prototype as a reader, hand upstream.
7. **Do not own** the publication manifest — that is TB2.1's `submissions/*.json` + `metrics.py` (and SWE-bench's `get_results.py`/`get_leaderboard.py`) plus the missing "merged == displayed" invariant and offline member digests. Contribute issues/PRs there.
8. **Do not build** a bundle wire envelope, signing, or a lineage vocabulary — borrow RO-Crate/in-toto/DSSE/PROV terms if and when needed (L6 §6(d)); `attestation.signature` should stay null until a signer exists.
9. **Do not present** trial-level byte sealing as the headline; keep it as an optional integrity signal for archives that lack content addressing. No documented failure in the corpus was prevented by it (L7 §6.2); the one place it directly helps is L5's ingest layer.

A negative paper — "campaign accounting and native prospective capture subsume most of a per-trial evidence envelope; the missing artifact is a per-row manifest with an expected-set check" — is, on these receipts, the truthful paper. It should not be written until experiments 1–2 below produce a measured result.

## 8. Implications for the central question

"What evidence is required for an independent person to reconstruct an evaluation claim?" — on these receipts:

1. **For the arithmetic: the per-instance artifacts plus a written rule.** Every real number in the corpus reproduced from per-instance records; none reproduced from a *written* rule. The rule was recovered by matching in every case. So the smallest missing evidence is a **declared aggregation/exclusion/uncertainty rule with its version**, next to the number — a few lines, publisher-owned, already prototyped by TB2.1.
2. **For membership: an expected set at every layer, held by a different actor than the record.** Harbor has it for trials; no leaderboard studied has it for rows. The failure "a merged 77.6% row silently vanished", "21 merged folders undisplayed", "scan stopped at [in-house value redacted]" is one failure with three faces, and no per-transition record can see it. This is the strongest thing the lanes did *not* say in so many words and it should shape the next design: **the record must be checked against an expected set, or it is decoration.**
3. **For instrument identity: prospective only.** Harness commit, image digest, dataset revision, provider-returned model, prompt digest, agent binary — none was recoverable retrospectively in any of the five cases; the ecosystems' own docs and scripts refer to mutable names (`main`, `:latest`, unpinned `load_dataset`). Eval Evidence cannot fix this; Harbor/task publishers can (task digest exists; the rest does not).
4. **For interpretation: out of scope.** Contamination, verifier validity, reference populations, metric-induced "emergence" all reconstruct perfectly and mean something else. Lineage makes such claims falsifiable; it does not make them true. Any tool that markets lineage as trust is mis-selling.
5. **The proposed abstraction is unnecessary as an abstraction and as a per-trial envelope**; the record is necessary and small; the honest per-field state is the one novel and portable piece; the biggest lever is a publisher-side manifest with an expected-set check plus three Harbor fields. A shrunk Eval Evidence that owns items 1–3 of §6, runs experiments 1–2 of §7, and writes the negative result is the outcome the receipts support.
